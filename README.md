# Huginn

Лендинг и личный кабинет для hCaptcha-инфраструктуры: **Next.js 16 / App Router, TypeScript, Tailwind CSS 4, Fastify 5, PostgreSQL, Prisma 6 и Recharts**. Сам движок решения CAPTCHA в проект не входит.

## Локальный запуск без Docker

Нужен **Node.js 22.21+**. Команды выполняются из корня репозитория.

```powershell
npm install
Copy-Item .env.example .env
npm run db:generate
```

В первом терминале запустите настоящий локальный PostgreSQL. Пакет `embedded-postgres` устанавливает бинарники из npm; Docker, системный сервис и отдельная установка PostgreSQL не нужны.

```powershell
npm run db:local
```

База `huginn` слушает только `127.0.0.1:54329`. Данные сохраняются в игнорируемой папке `.local/postgres`. Оставьте терминал открытым. На Windows остановка может завершить процесс PostgreSQL; при следующем запуске он выполняет штатное восстановление журнала. Это инструмент для разработки, не production-сервис. Не запускайте два экземпляра одновременно. На Linux запускать от обычного пользователя, не root.

Во втором терминале:

```powershell
npm run db:migrate
npm run dev
```

Откройте **http://localhost:3000**. Fastify работает на `127.0.0.1:4000`; Next.js проксирует `/api/*` в backend. Используйте адрес, совпадающий с `APP_ORIGIN`: проверка Origin защищает браузерные операции от CSRF. Если предпочитаете `http://127.0.0.1:3000`, измените `APP_ORIGIN` в `.env` и перезапустите приложение.

Если PostgreSQL уже установлен, укажите свой `DATABASE_URL` и пропустите `db:local`. Для Linux/macOS вместо `Copy-Item` используйте `cp .env.example .env`.

## Что работает

- Лендинг: responsive-композиция с фактурой ворона, возможности, Python/JavaScript, последовательность интеграции, тариф из API, FAQ.
- `/register`, `/login`: регистрация и вход с проверкой данных; выход отзывает текущую сессию.
- `/app`: баланс, решения, успешность завершённых задач, среднее время успешных решений, дневной график за 7/30/90 дней, типы и последние задачи. День статистики — UTC. Отсутствующие показатели показываются как `—`, без придуманных значений.
- `/app/tasks`: фильтр, пагинация, создание задачи, просмотр статуса и результата. Список незавершённых задач обновляется каждые 5 секунд.
- `/app/keys`: именованные ключи, однократный показ секрета, копирование, отзыв. В базе только SHA-256-хеши; максимум 20 активных ключей.
- `/app/billing`: баланс, транзакции и расширяемый checkout. Биллинг в целых микродолларах, без арифметики float при списании.
- `/app/settings`: имя, timezone, смена пароля с отзывом других сессий.
- `/docs`: публичный REST-контракт и исполняемые примеры без вымышленного SDK и деталей солвера.

Новые аккаунты получают **нулевой баланс**. По умолчанию провайдеры решения и оплаты отключены: соответствующие операции возвращают **503**, без списания денег, фальшивых токенов и фиктивного успешного пополнения.

## Dev-данные — только явно

Для просмотра заполненного кабинета измените в локальном `.env`:

```dotenv
DEMO_MODE="true"
DEMO_PASSWORD="your-unique-local-password-at-least-12-chars"
```

```powershell
npm run db:seed
```

Перезапустите `npm run dev`. Вход: **demo@huginn.local**, пароль из вашего `.env`. В кабинете появится постоянная отметка **DEVELOPMENT DEMO**. Это образцы записей в PostgreSQL, а не утверждения о производительности сервиса. Seed повторно не меняет существующий demo-аккаунт. Никаких demo-ключей или рабочих токенов не создаётся. Seed и `DEMO_MODE=true` запрещены в production. `.env` и база не попадают в Git.

## API

Публичная база локально: `http://localhost:3000/api/v1`.

| Метод | Путь         | Назначение                      |
| ----- | ------------ | ------------------------------- |
| GET   | `/balance`   | Баланс в USD                    |
| POST  | `/tasks`     | Создание hCaptcha-задачи        |
| GET   | `/tasks/:id` | Статус и результат своей задачи |

Заголовок: `Authorization: Bearer hg_live_…`. Создание принимает JSON `type: "hcaptcha"`, `websiteURL`, `websiteKey`. `Idempotency-Key` защищает повторные отправки от повторной резервации; при другом вводе с тем же ключом возвращается 409.

Статусы: `queued → processing → succeeded | failed`. При принятии задачи цена резервируется в одной транзакции с записью задачи и журнала. Успех фиксирует стоимость; ошибка возвращает резерв ровно один раз. Очередь сохраняется в PostgreSQL и использует атомарный захват задач. Зависшие задачи завершаются с возвратом. Токены результата очищаются спустя 24 часа. База дополнительно проверяет неотрицательный баланс и допустимые суммы.

API кабинета через тот же `/api`: `/auth/register`, `/auth/login`, `/auth/logout`, `/account`, `/account/password`, `/stats?days=30`, `/tasks`, `/keys`, `/billing`, `/billing/checkout`. Оно использует браузерную сессию, а не API-ключ. История задач и транзакций — по 20 записей, параметр `page`.

Пароли защищены `scrypt` с отдельной случайной солью. Сессии — случайные 256-битные токены с хранением хеша и сроком действия; cookie `HttpOnly`, `SameSite=Lax`, `Secure` в production. В production используется `__Host-` cookie. Fastify включает Helmet, лимит тела 64 КБ, Zod-валидацию, ограничения запросов и обезличенные ошибки. Внешние запросы не могут читать чужие задачи. Секреты и тела запросов не логируются.

## Подключение провайдеров

Границы интеграции определены в `server/providers.ts`: `SolverEngine` и `PaymentProvider`. Приватный движок должен находиться в отдельном сервисе. Публичный проект содержит только контракт отправки задачи и получения результата; алгоритмов, моделей и методов анализа в нём нет.

### Движок задач

Установите `SOLVER_PROVIDER=http`, `SOLVER_URL` и `SOLVER_SECRET`. Адаптер отправляет POST с Bearer-секретом и JSON `{ taskId, websiteURL, websiteKey }`. Ожидается `{ "token": "..." }`. Ошибка, некорректный ответ или timeout приводят к отказу задачи и возврату средств. Поддерживается ограничение `TASK_TIMEOUT_SECONDS`. Используйте `taskId` для идемпотентности на стороне приватного сервиса.

### Платежи

Установите `PAYMENT_PROVIDER=http`, `PAYMENT_URL`, `PAYMENT_SECRET` и независимый `PAYMENT_WEBHOOK_SECRET` длиной минимум 32 символа. Адаптер отправляет POST с Bearer-секретом:

```json
{
  "paymentId": "uuid",
  "amountMicro": "10000000",
  "currency": "USD",
  "returnURL": "https://your-domain/app/billing"
}
```

Ожидается `{ "reference": "provider-reference", "checkoutURL": "https://provider/checkout/..." }`. Возвращаемый URL должен использовать HTTPS. До подтверждения баланс не меняется.

Платёжный адаптер после подтверждения провайдером отправляет POST `/api/webhooks/payment` с **точными байтами JSON**:

```json
{
  "paymentId": "uuid",
  "reference": "provider-reference",
  "amountMicro": "10000000",
  "currency": "USD",
  "status": "confirmed"
}
```

- `X-Huginn-Timestamp`: Unix timestamp в секундах.
- `X-Huginn-Signature`: hex HMAC-SHA256 от `timestamp + "." + rawBody`, ключ `PAYMENT_WEBHOOK_SECRET`.
- Допустимое отклонение времени — 5 минут. При каждой повторной доставке подпишите новый timestamp.
- ID, reference, валюта и сумма должны совпадать с ожидаемым платежом. Адаптер должен повторять доставку при временной ошибке, в том числе если webhook опередил запись reference после checkout.
- Повторные и конкурентные подтверждения не зачисляют деньги повторно. Редирект из checkout сам по себе не является подтверждением оплаты.

Для конкретного платёжного SDK можно заменить реализацию `PaymentProvider`, сохранив проверяемую доставку подтверждений. Проект намеренно не подменяет отсутствующего провайдера тестовым успехом.

## Проверки

```powershell
npm test
npm run test:integration
npm run typecheck
npm run build
```

Интеграционные тесты требуют запущенную PostgreSQL и права создавать схемы. Runner создаёт уникальную временную схему, применяет миграции и удаляет только эту схему после выполнения; обычные данные и очередь приложения не затрагиваются. Можно указать отдельный `TEST_DATABASE_URL`. Запуск при `NODE_ENV=production` запрещён. Провайдеры в тестах — явно обозначенные изолированные fixtures, они не включаются в приложение. Проверяются сессии и их отзыв при смене пароля, CSRF, изоляция аккаунтов, ключи, конкурентные резервации, однократный возврат, idempotency, обработка задач, статистика и HMAC/replay платежей.

## Production

Используйте управляемую/отдельно обслуживаемую PostgreSQL с резервным копированием и timezone UTC. Выполните миграции и сборку. Установите `NODE_ENV=production`, `APP_ORIGIN=https://your-domain`, `DEMO_MODE=false`, реальные секреты и провайдеров. После этого `npm start` запускает Next.js и Fastify. Backend должен оставаться на loopback за Next.js/reverse proxy; доверяются только loopback-прокси. HTTPS обязателен. `API_INTERNAL_URL` задаётся до сборки Next.js, поскольку rewrite входит в конфигурацию сборки.

Default rate limit — 120 запросов/минуту на IP; вход/регистрация — 10 попыток/15 минут; checkout — 10/минуту. Для нескольких процессов API подключите общий store rate limiter и настройте proxy trust для вашей топологии. Текущий memory-store рассчитан на один процесс API. Email verification, восстановление пароля через email и возврат денег из кошелька не включены: для публичного запуска нужно добавить соответствующие операторские процессы, реальные контакты и политику хранения. Страницы Terms/Privacy содержат описание поведения приложения и явно требуют данных оператора; они не заменяют его юридические документы.

## Визуальный материал

Сайт использует только светлую бело-голубую и серую палитру. Hero состоит из текста слева и абстрактного крыла с интерактивным API-предпросмотром справа. Предпросмотр всегда на английском, не отправляет реальную задачу и показывает демонстрационный статус. Поддержка обычной hCaptcha и hCaptcha Enterprise указана в описании; логотипы Discord, Steam, Riot Games и Epic Games обозначают примеры сценариев, а не партнёрство. Источники логотипов: `public/images/brands/SOURCES.md`.

Фоновая фактура длинных маховых перьев создана встроенным ImageGen: `public/images/hero-raven-flight-feathers.png`, полный промпт — `docs/hero-raven-flight-feathers-prompt.txt`. Это фотографическая фактура вытянутых перьев ворона с тонкими волокнами в холодной голубо-серой палитре, без головы, глаза, текста или UI. Фон слегка размыт, постепенно затухает по краям и под текстом. Скриншоты-референсы не используются как готовые страницы.

Inter Variable с латиницей и кириллицей поставляется локально через `@fontsource-variable/inter` (OFL-1.1); запросов к Google Fonts нет. На кнопках при наведении или фокусе появляется фактура перьев `feather-material.webp` с движением из тёмного варианта. Нажатие запускает короткий взмах и рассеивание бело-голубых перьев на canvas; эффект сохраняется при переходе между страницами. Анимации отключаются при `prefers-reduced-motion`. API-пример использует моноширинный шрифт и многоцветную подсветку на тёмно-синей поверхности.

Материалы исходного тёмного варианта сохранены: `raven-blue-eye.png`, `raven-blue-eye-lossless.webp`, `raven-blue-eye.webp` и `docs/raven-image-prompt.txt`. Изменение голубой радужки создано встроенным ImageGen с сохранением формы глаза, зрачка, блика и освещения; эти исходники остаются доступны в репозитории.

Значок hCaptcha в hero и тарифах основан на [официальном SVG](https://www.hcaptcha.com/images/64da82f6bf67de1b127891ae_hcaptha-logo-white.svg): сохранена форма руки, палитра адаптирована к Huginn. Он обозначает поддерживаемый тип CAPTCHA. hCaptcha — зарегистрированная торговая марка Intuition Machines, Inc.; знак не означает партнёрство или одобрение Huginn.

Переключатель **RU / EN** доступен в навигации, формах и кабинете. Выбор хранится в cookie `huginn_locale` на год, читается сервером до рендера и сохраняется между страницами. Переводы интерфейса лежат в `lib/i18n.ts`, контекст — в `components/i18n.tsx`. Документация и сообщения интерфейса переводятся; имена полей REST API, код, токены, пользовательские данные и идентификаторы остаются без изменений. Даты используют язык интерфейса и часовой пояс аккаунта.
